# Contributing

Thanks for improving this infrastructure template.

## Development guidelines

- Keep changes generic and reusable.
- Never commit credentials, private keys, account IDs, or production hostnames.
- Prefer placeholders in examples (for example `your-domain.example`).
- Keep scripts POSIX/Bash compatible and idempotent where possible.

## Pull requests

1. Open an issue describing the problem or proposal.
2. Submit focused pull requests with clear rationale.
3. Include validation notes (for example shell syntax checks).

## Code of conduct

Be respectful and collaborative in all discussions and reviews.
